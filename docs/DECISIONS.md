# Решения (decision log)

Формат: контекст → выбор → альтернативы. Необратимые решения согласуются с
владельцем проекта, остальные фиксируем здесь сами.

## D-001: Движок — Godot 4.5.1, а не браузерный стек

- **Контекст:** master prompt описывал браузерную игру (TypeScript + Vite +
  Three.js + Node/WS). Владелец проекта явно потребовал Godot 4.5.1 и НЕ браузер.
- **Выбор:** Godot 4.5.1 + GDScript, десктоп.
- **Альтернативы:** браузерный стек точно по промпту (отклонено владельцем);
  Godot + web-экспорт (отклонено, возможно позже отдельным решением в фазе 9).

## D-002: Своя модель машины, не VehicleBody3D

- **Контекст:** master prompt требует тюнингуемую модель шин и кузова («must be
  our own so we can tune it»).
- **Выбор:** RigidBody3D + собственные raycast-колёса, своя модель шин
  (упрощённый Pacejka). VehicleBody3D не используем — чёрный ящик.
- **Альтернативы:** VehicleBody3D (быстрый старт, но нет контроля и тюнинга).

## D-003: Физика на фиксированном шаге 120 Hz

- **Контекст:** промпт требует фиксированный тик 120 Hz, независимый от FPS.
- **Выбор:** `physics/common/physics_ticks_per_second = 120`, вся симуляция в
  `_physics_process`.
- **Альтернативы:** переменный шаг (проще, но недетерминирован).

## D-004: Коллизии — встроенный PhysicsServer3D

- **Контекст:** промпт разрешал WASM-движок (Rapier) только для коллизий.
- **Выбор:** встроенный физический сервер Godot для коллизий; шины и кузов — свои.
- **Альтернативы:** Rapier через godot-rapier плагин (лишняя зависимость).

## D-005: Доки на русском, идентификаторы кода — английские

- **Контекст:** репозиторий публичный, промпт писался на английском, но владелец
  проекта общается на русском.
- **Выбор:** документация — русский язык; код, комментарии в коде, коммиты —
  английские идентификаторы, комментарии могут быть на русском.
- **Альтернативы:** всё на английском (менее удобно владельцу сейчас; локализация
  доков возможна позже).

## D-006: Рабочее название — Apex GP

- **Контекст:** юридические правила промпта запрещают F1/Formula One и реальные
  бренды; нужен нейтральный вымышленный титул.
- **Выбор:** «Apex GP», все команды/трассы/спонсоры вымышленные.
- **Альтернативы:** любое другое название — поменять стоит одну константу
  (`application/config/name`), предложение от владельца приветствуется.

## D-007: Ввод — клавиатура первой, всё через Input Map

- **Контекст:** промпт требует touch + keyboard + gamepad с ремапом; владелец
  выбрал «клавиатура» для первой версии.
- **Выбор:** все действия объявлены в Input Map (`throttle`, `brake`, ...),
  код читает только действия, не клавиши — touch/gamepad добавляются в фазе 9
  без правки логики.
- **Альтернативы:** прямой опрос клавиш (быстрее, но ломает ремап).

## D-008: Кокпит — основная камера, chase — дебаг

- **Контекст:** промпт планировал chase-камеру в фазе 1; владелец выбрал камеру
  из кабины.
- **Выбор:** кокпит (FPV) — основная; chase-камера остаётся переключателем V для
  отладки физики.
- **Альтернативы:** chase основной (отклонено владельцем).

## D-009: Тесты — чистые SceneTree-скрипты без плагинов

- **Контекст:** нужен headless-запуск в CI и локально, минимум зависимостей.
- **Выбор:** `extends SceneTree` + `--script`, exit code как результат.
- **Альтернативы:** GUT/gdUnit4 (фичастее, но плагин в репо и версионная связка
  с Godot).

## D-010: Неткод и лиги — не реализуем до фазы 3

- **Контекст:** промпт описывает большой продукт; попытка сделать всё сразу —
  главный риск срыва.
- **Выбор:** архитектура оставляет место (data-driven трассы, общие скрипты),
  сетевого кода нет до фазы 3.
- **Альтернативы:** строить неткод параллельно (отклонено: неоправданная
  сложность на старте).

## D-011: Таргет — мобильные устройства (Android/iOS), десктоп — дев-платформа

- **Контекст:** владелец подтвердил, что игра мобильная. Master prompt изначально
  требовал 60 FPS на средних телефонах — теперь это основной критерий, а не
  пожелание.
- **Выбор:** рендерер **Mobile** (Vulkan mobile) вместо Forward+; ориентация
  sensor landscape; тач-контролы переезжают из фазы 9 в **фазу 1** (экранные
  руль/газ/тормоз, эмуляция тача мышью на десктопе для отладки). Бюджеты
  производительности из PLAN.md становятся обязательными с фазы 1. Сборка APK —
  через CI (export templates + Android SDK в Actions) или локально; рецепт
  документируется в фазе 1.
- **Альтернативы:** Compatibility-рендерер (GL, шире совместимость со слабыми
  устройствами, но беднее — запасной вариант, если Mobile не потянет часть
  целевых телефонов); десктоп-таргет с портом «потом» (отклонено владельцем).

## D-016: Чемпионат оффлайн — переиспользуем лиговый ResultsStore (0.8.0)

- **Контекст:** Phase 3 (онлайн-ядро лиги) заморожена: нет VPS, сервер поднимать
  не на чем. В меню висела заглушка CHAMPIONSHIP, а `ResultsStore` (сезоны,
  очковая система, агрегация standings) уже реализован и лежал без дела.
- **Выбор:** режим чемпионата целиком оффлайн. Сезон = расписание из 4/6 раундов
  по каталогу трасс (циклически) + сложность/круги, зафиксированные на старте;
  ростер — 8 вымышленных имён (YOU + 7 AI), хранится в сезоне для стабильности.
  Состояние сезона — `user://championship.json`; каждый завершённый раунд
  записывается через `ResultsStore.save_race()` с ключом сезона `champ-N`
  (N растёт, чтобы старые сезоны не смешивались). Таблица чемпионата — готовая
  агрегация `ResultsStore.standings()`. Физика не затронута.
- **Альтернативы:** отдельный стор результатов для чемпионата (дублирование
  протестированной логики — отклонено); ждать Phase 3 с VPS (заморожено
  владельцем); календарь с «двойными» раундами на одной трассе — поддержан
  самим циклом каталога.
- **Следствия:** при появлении VPS сезон чемпионата и лига будут говорить
  с сервером одним и тем же форматом classification; UI-панель чемпионата
  сознательно без autoload-зависимостей в _init — тестируется headless.


## D-017: Погода — скаляр wetness и шинные оценки, без реворка физики (0.10.0)

- **Контекст:** фаза 6 (погода) по роадмапу большая: динамика дождя,
  высыхание трассы, лужи. Владелец заморозил реворк физики, но просил
  «что-то новое». Нужен был погодный слой, который не трогает
  откалиброванную модель шин 0.7.0 и не ломает 333 проверки.
- **Выбор:** погода = один скаляр wetness 0..1 на гонку (сейчас фиксирован:
  dry 0 / light 0.45 / heavy 0.85), шина = пара оценок grip_dry/grip_wet и
  wear_dry/wear_wet, линейно интерполируемых по wetness. Сухой трек + слики
  дают множитель ровно 1.0 — вся сухая физика 0.9.0 бит-в-бит прежняя.
  Оценки живут в vehicle.json (tires.compounds) — тюнинг без кода. AI
  выбирает лучший compound автоматически (best_for_wetness) и умножает свой
  mu_eff; вейты на сухом перегреваются (wear ×1.8) — цена неправильного
  выбора для игрока. Погода раундов чемпионата детерминирована ключом
  сезона (seed хеша) и пишется в season-файл один раз при старте сезона —
  календарь стабилен между запусками даже если hash() сменит алгоритм в
  будущих версиях движка (пересчитываются только будущие сезоны). Time Trial
  всегда сухой: рекорды и призраки остаются сравнимыми.
- **Альтернативы:** динамический дождь с высыханием колеи (отложено в
  KNOWN_ISSUES — отдельная механика прогресса wetness по кругам);
  менять TireModel/Pacejka-коэффициенты (отклонено — реворк физики
  заморожен владельцем); отдельная «мокрая» физика (отклонено — раздвоение
  тестируемой модели).
- **Следствия:** фаза 6 не закрыта, а открыта в lite-виде: высыхание колеи,
  лужи/брызги геометрией и звук дождя — поверх этого же скаляра. Слой
  погоды чистый (WeatherState/TyreCompound без сцены) — тесты гоняют
  headless, AI-драйвер получает уже готовый множитель.


## D-018: Аудит 0.10.1 — оконный прогресс, геометрический DRS-гэп, явная инерция

- **Контекст:** внешний аудит 0.9.0 нашёл перфоманс и логические проблемы:
  линейный поиск прогресса на каждый тик каждой машины, круговую поправку в
  `_distance_ahead` (схлопывала дистанцию в 0 м и открывала ложный DRS),
  игнорируемую инерцию кузова из JSON, пересоздание строк башни standings.
- **Выбор:** прогресс гонки — оконный поиск ±24 точки вокруг последнего
  индекса с фулл-сканом на первом тике и при промахе >20 м (телепорт/ресет);
  «на треку»-дистанции (DRS, ближайшая впереди) — чистая геометрия без учёта
  кругов, все круго-aware величины (интервалы, laps_behind) живут в
  `_race_distance()`; инерция кузова задаётся явно из vehicle.json (оси
  Godot: X = питч, Y = рыскание, Z = ролл); строки башни строятся один раз
  и переставляются `move_child`; гэп-колонка — dirty-check 4 Гц; тени
  направленного света — 40/60/100 м по пресету качества.
- **Альтернативы:** spatial-хеш точек трассы (избыточно при ≤744 точках и
  120 Гц); DRS только против машин в круге (не соответствует F1-семантике
  «любая машина впереди в пределах 1 с»); оставлять derived-инерцию Godot
  (отклонено — расходится со спецификацией машины).
- **Следствия:** сухая физика не менялась, кроме явной инерции: тормозной
  путь, симметрия руления и время круга AI — в допуске тестов; C2 из аудита
  (AI-индекс после ресета) проверен и уже корректен: `reset_to_line()`
  сбрасывает `_searched` и делает полный рескан.
